Federated Ingestion Platform

How a pipeline gets built, deployed, and watched

This app takes a user from an empty wizard to a running, monitored data pipeline. Click any step below for what it does, which files implement it, the backend/data services it hands off to, and whether it's really wired up or simulated for the demo.

Data services & config API — what we're using
The intended production path is UI → Config API → GitHub → Airflow → a GCP data service. None of the boxes below exist as real backend code in this repo (see "External systems" in the System architecture tab) — they're what the wizard's steps and job history are designed to hand off to.
Config API
Connections store (host, credentials, auth) Pipeline config commit (Review & deploy) Column mapping persistence
GCP Data Services
Dataflow Dataproc Cloud Data Fusion GCS BigQuery
Orchestration & delivery
GitHub (commit-triggered deploy) Airflow (cron schedule + DAG run) Job History (run status, logs)
Connections & source/target types
PostgreSQL Oracle Kafka GCS BigQuery
AI / RAG layer
TF-IDF vector store (local, in-browser) LLM endpoint — Groq, OpenAI-shaped API
Frontend runtime
React 19 + TypeScript Vite 8 localStorage (Connections persistence)
Reading the labels: "Real" means the behavior actually runs in this codebase (client-side logic or localStorage). "Simulated" means it's faked with setTimeout/Math.random for the demo — no server exists. "Mixed" means part of the stage is real and part is a mock standing in for a future service.
